Manufacturing Project Visibility & ClickUp Synchronization

A deployed automation that gives project managers one synchronized view of ~500 manufacturing projects across Epicor and ClickUp — updating each in about two minutes instead of ten.

Overview

Designed and fully deployed an automated project-visibility system that synchronizes engineering and manufacturing information across Epicor, engineering spreadsheets, Excel, Power Automate, and ClickUp.

Before the system was introduced, updating an individual project required roughly 10 minutes of manual work. The deployed automation performs the same update autonomously in about two minutes — an 80% reduction that saves roughly eight minutes per project.

The system manages approximately 500 project records and maintains each one throughout its lifecycle: from initial engineering activity through manufacturing, galvanizing, shipping, and completion.

Problem

What needed solving.

Project information was distributed across Epicor, engineering spreadsheets, and other operational data sources. Project managers did not have a single synchronized view showing the current state of engineering, manufacturing, and shipping activity.

Manually creating and updating project records required roughly 10 minutes per project. At a scale of about 500 records, this created substantial repetitive work and made it difficult to maintain consistent, current project information.

The synchronization also had to account for changing source data, incomplete records, processing failures, duplicate updates, long-running flows, and projects transitioning from active work into completion.

Solution

How I approached it.

I developed a multi-stage automation architecture that collected engineering and Epicor data, detected new or changed projects, queued the required work, and synchronized the results into structured ClickUp projects.

Each project contained a summary and detailed engineering and manufacturing milestones. The system updated dates, statuses, custom fields, and lifecycle information based on the latest available source data.

To improve reliability, I incorporated project-state tracking, queued processing, change detection, validation, retry and failure handling, stale-record recovery, controlled batching, and completion-handoff logic.

System Architecture

Five layers, one flow.

Epicor Data Layer

A Business Activity Query collects order info, need-by dates, manufacturing start/complete dates and status, job counts, galvanizing requirements and completion, and shipping status and dates.

Engineering Data Layer

Engineering spreadsheet data supplies engineering status, order dates, and project-identification fields.

State & Queue Layer

Excel tables hold configuration, the sync queue, project state, an Epicor snapshot, refresh status, and an error log — used to tell whether a project is new, changed, already synced, or processing.

Automation Layer

Power Automate flows handle Epicor refresh, queue generation, stale-processing recovery, selected-project processing, ClickUp creation and updates, milestone sync, validation, error recovery, and completed-project handoff.

ClickUp Layer

The project-management interface: each record holds a summary task and structured engineering and manufacturing milestones, so managers see current state without consolidating systems by hand.

Project Lifecycle

How a project moves through the system.

  1. Engineering and Epicor data is refreshed.
  2. Source records are normalized and validated.
  3. New or changed projects are identified.
  4. Required work is added to the synchronization queue.
  5. Queue records move through pending, processing, success, or failure states.
  6. New ClickUp project structures are created from a controlled template.
  7. Existing project dates, statuses, and custom fields are updated.
  8. Manufacturing, galvanizing, and shipping milestones are synchronized.
  9. Errors are logged and recoverable failures are retried or reset.
  10. Shipped projects are transitioned from active to completed project structures.

Key Engineering Lessons

What I'd carry forward.

This project demonstrated that a production automation system requires more than connecting two APIs. The solution had to maintain state over time, detect meaningful source changes, prevent duplicate work, handle incomplete data, and recover from partial failures.

I gained experience designing long-running workflow automation, debugging complex date and source-data issues, managing API constraints, and building a system that remained understandable after growing across multiple flows and data sources.

The project also strengthened my ability to work directly with a stakeholder, translate operational requirements into technical architecture, and independently carry a system from concept through production deployment.
