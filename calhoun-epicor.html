Project 03

SolidWorks-to-Epicor Manufacturing Middleware

A Python middleware that automates the transfer of engineering data from SolidWorks assemblies into Epicor ERP — safely and traceably.

Theme Garnet
RoleSolo — design & development
YearTBD
ToolsPython · SolidWorks · Epicor ERP · REST APIs · Manufacturing Automation · Desktop UI
TypeERP integration / middleware

Overview

A Python desktop middleware that automates the transfer of engineering data from SolidWorks assemblies into Epicor ERP. It replaced a largely manual workflow in which engineers had to review assembly information and recreate the corresponding parts, revisions, bills of materials, and manufacturing operations inside Epicor.

The application scans a SolidWorks assembly, extracts and organizes engineering data — part numbers, descriptions, materials, weights, assembly relationships, BOM structures, revisions, and operations — and presents it through a desktop review interface before any ERP changes are made. Engineers can review and edit defined fields while the system validates the data and determines what already exists in Epicor.

Highlights

  • Safe, traceable ERP automation — existence, dependency, and validation checks, dry-run and preflight workflows, live-write protection, logging, and post-write verification.
  • End-to-end engineering-data extraction — parts, revisions, BOMs, and manufacturing operations pulled from hierarchical SolidWorks assemblies.
  • Editable review-and-validate workflow that lets engineers check and correct data before anything is written to Epicor.

Problem

What needed solving.

The existing workflow was largely manual: engineers reviewed assembly information and recreated the corresponding parts, revisions, bills of materials, and manufacturing operations inside Epicor by hand. That process was repetitive and slow, invited inconsistency, and left room for errors to reach the live ERP environment.

Solution

How I approached it.

A major focus of the project was making ERP automation safe and traceable rather than simply automating API calls. The application performs Epicor existence checks, dependency and validation checks, prevents known bad data from reaching the live environment, supports dry-run and preflight workflows, and verifies planned actions before executing writes. Import results, errors, and relevant workflow activity are logged to provide an audit trail and simplify troubleshooting.

System Design

A layered architecture.

The application uses a layered architecture that separates concerns, keeping the system maintainable and extensible for additional ERP automation workflows.

User Interface

Desktop review screen where engineers inspect and edit extracted data before any ERP change is made.

SolidWorks Extraction

Scans assemblies and pulls part numbers, descriptions, materials, weights, relationships, BOM structures, revisions, and operations.

Workflow & Business Logic

Validation, existence and dependency checks, dry-run/preflight, and the rules that decide what is safe to write.

Shared Engineering Models

Common data models for parts, revisions, BOMs, and operations, used consistently across the application.

Epicor Service Communication

REST API and business-service calls that perform verified writes into Epicor ERP.
